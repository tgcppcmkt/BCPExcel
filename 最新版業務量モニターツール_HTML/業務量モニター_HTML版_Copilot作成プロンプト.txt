==================== プロンプト本文 ====================

あなたは、日本語の業務用Webアプリを実装する開発者です。
以下の仕様に沿って、職場で使用する「業務量モニター3.0tag HTML版」を作成してください。
担当CAの業務量をCSVから取り込み、Excelの振分表と照合して担当者別にランキング表示するアプリです。
平日・土日の画面を切り替えられ、CAチェック、サポート投入・解除、サポ希望、コミット・取消を、共有フォルダを通じて複数の利用者で共有します。

計画や画面のモックだけで終わらせず、ファイル選択、集計、共有保存まで動作するファイル一式を作成してください。
CSVやExcelを読み込む部分、共有フォルダに保存する部分を、ダミー処理やTODOのまま残さないでください。

1．進め方と、参考資料の扱い

・HTML最新版の元コードが添付されている場合は、最初にHTMLと各JSを読み、既存の実装を基準にしてください。
・元コードがある場合は、計算式、JSON形式、識別子、入力取消、保存待ちの処理を再利用してください。外観だけ似た別アプリに置き換えないでください。
・この仕様と元コードに食い違いがあれば、該当箇所と影響を具体的に示してください。無断で片方の機能を削除しないでください。
・元コードがない場合は、この仕様から新規作成してください。既存データとの互換性を確認できない部分は、互換性を検証済みと記載しないでください。
・参考資料が足りない場合も、確定している部分の実装は進めてください。本当に判断が必要な点に限って質問してください。
・HTAや古いダウンロード版をベースにしないでください。
・既存レポジトリにアクセスできる場合も、作業は別フォルダまたは作業用コピーで行い、元のファイルを上書きしないでください。
・コミット、push、公開、外部サービスへの送信は行わないでください。

2．動作環境と、構成の条件

・Windowsの通常のMicrosoft Edgeで使用します。対応APIがあるChromeでも動く構成にしてください。
・利用場所は、AWS内の職場環境です。外部インターネットへのアクセスが制限されています。
・アプリを実行する際に外部通信、CDN、外部フォント、外部API、アクセス解析を必要としないでください。
・HTMLとJavaScriptを同じフォルダに配置し、展開したHTMLファイルをブラウザで開いて使用する構成にしてください。
・アプリ起動のためにNode.js、Python、Webサーバー、インストーラー、管理者権限を要求しないでください。
・React等のビルド環境を必須にせず、通常のHTML、CSS、JavaScriptで実装してください。
・HTA、ActiveX、COM、WScript、PowerShell、OSコマンド、Excelの自動操作は使用しないでください。
・CSV、Excel、共有フォルダへのアクセスは、ブラウザのFile System Access APIを使い、利用者が選択・許可した範囲で行ってください。
・対応APIが利用できない場合は、理由を日本語で表示してください。社内ポリシーやブラウザの制限を回避する仕組みを作らないでください。
・ファイル選択と権限要求は、ボタンのクリック等、利用者の操作を起点に行ってください。
・ブラウザの権限とWindows・共有フォルダのアクセス権は別です。ブラウザの許可を「管理者権限」と説明しないでください。
・配布フォルダ内のファイルをすべて展開してから使う前提とし、ZIP内のHTMLを直接開く使い方は案内しないでください。

3．ファイル構成と、メンテナンスのしやすさ

次の役割に分けてください。元コードがある場合は、このファイル名と役割を維持してください。

WorkloadRanking.html
  画面、CSS、操作、表示更新、ランキング、対応余力。
workload-config.js
  平日ログと共通振分表の列・行・文字コード・除外設定。
workload-core.js
  CSVの解析、値の検証、CA照合、担当者別データの構築。
workload-browser.js
  ファイル・フォルダ選択、権限、設定記憶、CSV・Excelの読込。
workload-share.js
  日付別の共有保存、操作履歴の読込、保存待ち、競合処理。
workload-weekend.js
  土日用の列・行設定、3つのCSVの集計、対象項目の選択。
README_HTML.txt
  起動方法、初回設定、毎日の操作、変更可能な設定、制約。

・列番号はExcelの列記号、行番号は1から数えた番号で指定できるようにしてください。
・非エンジニアでも、設定ファイルの先頭を見れば変更箇所が分かる日本語コメントを付けてください。
・列変更のために複数の関数内にある数値を探して直す構成にしないでください。
・振分表の列設定は平日・土日で共通です。土日ログの列変更は、土日用設定だけで対応できるようにしてください。
・CSSのテーマ切替だけで処理内容が変わらないようにしてください。
・元コードの不要なHTA専用処理を復活させないでください。

4．画面全体

・日本語UIにしてください。画面名は「業務量モニター3.0tag HTML版」です。
・上部にタイトルと設定、メインに担当者ランキングと右側のダッシュボードを配置してください。
・広い画面では左側がランキング、右側が件数・対応余力のダッシュボードです。
・1920×1080程度のモニターで、サポート欄が押しつぶされず、主要操作が見えるようにしてください。
・現在の幅感の目安は、ページ最大幅1760px、最小幅900pxです。1280px以上では左右配置、狭い画面では縦配置にします。
・ランキングと右側の表示領域は、画面の高さに合わせてスクロールできるようにしてください。
・担当者行と担当CA詳細の数値の位置をそろえ、どの数値がどの列か読みやすくしてください。
・CA名、組織名、長いサポート氏名、長いフォルダ名が他のボタンに重ならないようにしてください。
・設定欄は「設定」という見出しで常に表示します。折り畳みにはしません。
・余力再計算ボタンの右横に、「平日」「土日」の2択スイッチを配置してください。
・初期表示は平日です。曜日による強制切替はしないでください。
・利用者が分かるよう、選択中のモードを明確に表示し、aria-pressed等にも反映してください。
・初回の集計前は、架空の担当者や件数を表示しないでください。集計時刻は空欄、対応余力は「未集計」です。
・読み込み中、保存中、権限不足、設定不足、競合は、必要な場所に日本語で表示してください。
・成功時だけの見た目を作らず、取消やエラーの状態も実装してください。

6．初回設定と、記憶する情報

設定欄の表示：
平日：［共有］フォルダ名　［未読］フォルダ名　［フラグ］フォルダ名　［振分表］ファイル名
土日：［共有］フォルダ名　［土日ログ］フォルダ名　［振分表］ファイル名

・各ボタンの右横に、選んだフォルダ名またはファイル名を表示してください。
・未設定なら「未設定」、振分表を未選択なら「未選択」と表示してください。
・長い名前は省略表示し、カーソルを合わせると名前の全文が分かるようにしてください。
・共有ボタンを特別に目立つデザインにせず、他の設定ボタンとそろえてください。
・共有フォルダと振分表は、平日・土日で同じものを使います。
・共有は読込・書込権限、ログの親フォルダと振分表は読込権限を要求してください。
・設定は、ブラウザのIndexedDBにファイル・フォルダのハンドルとして記憶してください。
・現在の記憶先は、データベース名WorkloadRankingHTML、ストア名handlesです。元コードがある場合は互換性を維持してください。
・共有先には安定した識別子を割り当て、保存待ちの操作が別の共有先に送られないようにしてください。
・同じブラウザのプロファイルで開き直した場合、設定した場所を再利用できるようにしてください。
・ただし、記憶された場所と継続中の許可を区別してください。再度の許可が必要なら、利用者の操作から確認してください。
・ブラウザのデータ削除、プロファイル変更、アプリを置く場所の変更等では再設定が必要になる可能性を案内してください。
・Windowsの文字列パスを書くだけで、初回から無許可アクセスできるという実装・説明にしないでください。
・CSV本体や集計結果を、フォルダ設定の記憶と混同しないでください。ログは利用者が集計時に選びます。

7．読込先のフォルダ構成

パソコンの当日の日付を使って、記憶した親フォルダから対象フォルダを開きます。
以下のyyyy、mm、dd、yyは例ではなく、実行日の数値で置き換えてください。

未読：選択した親フォルダ／yyyymm／mmdd
フラグ：選択した親フォルダ／yyyymm
土日ログ：「ログ」の親フォルダ／yymmdd
共有：選択した共有先／WORKLOAD_HTML_DATA／yyyymmdd

例：2026年10月10日に実行した場合
未読：未読の親フォルダ／202610／1010
フラグ：フラグの親フォルダ／202610
土日：選んだログフォルダ／261010
共有：選んだ共有フォルダ／WORKLOAD_HTML_DATA／20261010

・土日ログの設定では、通常「ログ」フォルダそのものを選び、その配下の日付フォルダを使います。
・振分表は共通のExcelファイルを直接選択し、記憶します。
・ログの対象フォルダが存在しなければ、どのフォルダが不足しているか表示してください。
・対象フォルダがないとき、別の日付や親フォルダのCSVを黙って取り込まないでください。
・CSV選択ダイアログは対象フォルダから開き、選択されたファイルがその対象フォルダ内にあることをハンドルのresolve等で確認してください。
・ログや振分表を変更・上書きしないでください。共有保存以外は読み取りです。

8．ログ集計ボタンの共通動作

1）必要な設定がそろっているか確認します。
2）共有先を再接続・再読込し、必要な権限を確認します。
3）確定済みで保存待ちになっている共有操作があれば、同じ共有先に保存を再試行します。
4）当日・当月の対象フォルダを開いて、CSVを選択します。
5）CSVと設定済みの振分表を読み込み、すべての検証・照合・計算が成功してから画面に反映します。
6）成功した時点のPCの時刻をHH:mmで集計時刻に入力し、対応余力を計算します。

・平日は未読CSV、フラグCSVの順に、2回選択します。
・土日はCSVを1つずつ、3回選択します。3つをまとめて自動で全ファイル読込する方式にはしません。
・土日の3つは別のファイルです。同じFileSystemFileHandleを再度選んだ場合は、isSameEntry等で重複を検出してください。
・別ファイルでも組織・CAが同じ行は、仕様に従って合算します。ファイルの重複とCA行の重複を区別してください。
・選択途中で取り消した場合、現在表示中の集計を失わせないでください。
・3つ目でエラーになった場合も、最初の2つだけを画面に反映しないでください。
・設定不足なら、先に設定する項目を日本語で案内してください。
・途中の非同期処理でユーザー操作の有効期間が切れた場合は、「ログ集計を続ける」等の案内と「CSVを選択」「許可を確認」のボタンを表示し、改めて利用者の操作から進めてください。
・入力中のサポート氏名や確認ダイアログを、読込失敗によって勝手に消さないでください。
・集計の連打、保存中の集計、ファイル選択中のモード切替で処理が二重に走らないようにしてください。
・余力再計算は、CSVの再読込とは別です。

廃止済みのため、次の独立ボタンは設置しないでください。
「未読CSV選択」「フラグCSVを選択」「共有履歴を出力」「保存待ちの控えを出力」「再読み込み」

9．平日用設定

初期設定は次の内容にしてください。列記号・開始行をここだけで変更できるようにします。

var WorkloadConfig = {
    unread: {
        startRow: 3,
        charset: "auto",
        columns: {
            organization: "C",
            caName: "E",
            unreadBase: "H",
            unreadSubtract: ["M", "N", "O"],
            unsorted: "R"
        }
    },
    flag: {
        startRow: 3,
        charset: "auto",
        columns: {
            organization: "C",
            caName: "E",
            flag: "F"
        }
    },
    assignment: {
        sheetName: "CA振分表",
        startRow: 3,
        columns: {
            organization: "C",
            caName: "E",
            calib: "F",
            team: "K",
            staff: "L",
            canvas: "M"
        }
    },
    capacity: {
        hourlyRate: 16,
        excludedStaffNames: ["担当なし", "札幌担当", "新潟担当", "首都圏担当"],
        excludedTeams: ["担当なし", "札幌", "札幌担当", "新潟", "新潟担当", "首都圏", "首都圏担当"]
    },
    merge: {
        unassignedStaffName: "担当なし",
        unassignedTeam: "担当なし",
        duplicateLogRows: "sum"
    }
};

平日の計算：
・未読CSV、フラグCSV、振分表は、1・2行目を除外し、3行目からデータを読みます。
・CAの純粋未読 ＝ 未読CSVのH列 − M列 − N列 − O列。
・CAのフラグ ＝ フラグCSVのF列。
・CAの未仕分 ＝ 未読CSVのR列。
・CAの合計 ＝ 純粋未読 ＋ フラグ。
・未仕分は、表示しますが合計・ランキングの通常の合計値には含めません。
・純粋未読が負になった場合は、0に丸めず、行番号と列設定を確認するエラーにしてください。
・同じ組織・CA名のログ行は、duplicateLogRowsがsumなら合算、errorなら停止です。
・行番号や列名を含むエラー表示にして、どこを直せばよいか分かるようにしてください。

10．土日用設定と集計

土日用設定は、workload-weekend.jsの先頭にまとめてください。
初期設定は次のとおりです。

var WorkloadWeekendConfig = {
    headerRow: 2,
    startRow: 3,
    columns: {
        organization: "C",
        caName: "D",
        items: ["F", "G", "H", "I", "J", "K", "L", "M"],
        unsorted: "R",
        reference: "Q"
    }
};

・土日の組織はC列です。B列はエリアなので、振分表との照合に使わないでください。
・CA名はD列です。平日のE列と混同しないでください。
・項目名はCSVの2行目から取得します。1行目からではありません。
・件数は3行目から読みます。
・F～M列の8項目を、設定の配列の順番で集計します。
・R列は未仕分、Q列は参考項目です。どちらも表示だけに使います。
・3つのCSVを、組織＋CA名のキーで合算してください。
・3つのCSVは、各対象列の項目名が一致しているか確認してください。前後・全角を含む空白の扱いをそろえて照合します。
・1つ目と項目名が異なるCSVを、そのまま同じ項目として合算しないでください。
・見出しが空欄なら、F列、G列等の列名を使います。未仕分の空欄見出しは「未仕分」を使います。
・F～M列の項目名は週末によって変わるため、固定の日本語名にしないでください。
・組織・CA名・項目列の指定が重複している、開始行が見出し行より前、項目配列が8列ではない等の設定ミスも検出してください。
・件数の合算で安全な整数の範囲を超える場合は、エラーにしてください。
・土日にはチーム分けがありません。ランキング、詳細、絞り込み、チェック未集計にチームを表示しないでください。
・共通振分表の元データは変更せず、土日の処理だけチーム列を使わないようにしてください。
・土日ではチーム名による対応余力の除外を行いません。除外担当者名の設定は維持します。
・土日の処理を追加するために、平日の列、計算式、CAチェックの動作を変えないでください。

11．振分表との照合

・平日・土日とも、同じExcelの「CA振分表」シートを使います。
・照合キーは、組織＋CA名です。CA名だけで結合しないでください。
・組織、CA名、担当者名の前後空白と、照合用の全角・半角を含む空白の扱いを統一してください。
・異なる組織に同名のCAがいても、別のCAとして扱ってください。
・照合キーを単純な区切り文字の連結にして、名前の中の記号と衝突させないでください。
・元コードのキー形式は、空白を除いた値を用い、@＋組織の文字数＋:＋組織＋|＋CA名の文字数＋:＋CA名です。元コードがある場合はこれを維持してください。
・振分表に存在するCAは、CSVに行がなければ0件として表示してください。
・ログにあるCAが振分表に見つからなければ、「担当なし」にまとめ、照合漏れを確認できるようにしてください。
・振分表の担当者が空欄のCAも、「担当なし」です。
・正しく対応するCAを、土日のB列・C列の取り違えによって「担当なし」にしないでください。
・同じCAの振分表行が複数あり、担当者・チーム・リンクが一致する場合は重複行として扱います。相違する場合は、勝手に最後の行を採用せずエラーにしてください。
・平日の通常担当者が複数の異なるチームに割り当てられていたら、振分表の不整合として停止してください。
・担当なし等の除外区分は、平日ではチームごとに別の行になる場合があります。土日はチームを使いません。
・「担当なし」等の除外区分はランキングに表示できますが、全体件数と対応余力の対象人数から除外します。
・担当者数・CA数の表示と、対応余力の対象人数は区別してください。CA総数は除外区分も含みます。

12．CSV・Excelの読込と検証

・CSVは、カンマ、引用符、引用符内の改行、二重引用符、BOM、CRLF/LFを正しく解析してください。
・UTF-8、Shift_JIS、UTF-16に対応し、自動判定と設定による指定を用意してください。
・復元不能な文字化けは黙って置換せず、検出して説明してください。
・完全な空行は読み飛ばします。組織・CA名が欠けたデータ行は読み飛ばさずエラーにしてください。
・必要列までない行を、0件の正常な行として扱わないでください。
・件数の空欄は0です。全角数字は半角へそろえ、正しい桁区切りのカンマは許容してください。
・負数、小数、文字混在、不正な桁区切り、安全な整数を超える値はエラーにしてください。
・Excelは.xlsxと.xlsmを対象とし、ZIP内のXMLから必要なシート・セル・リンクを読みます。
・.xls、.xlsb、暗号化されたExcel等、対応していない形式は、対応しているように見せず説明してください。
・.xlsmのマクロは実行しないでください。Excelの数式も実行・再計算しません。
・Excelの既存のセル値を読み、ハイパーリンクの関連情報、または文字列URLのHYPERLINK数式からリンク先を取得してください。
・外部参照ブックやXMLの外部実体を取りに行かないでください。
・現在のExcel展開は、ブラウザのDecompressionStreamのdeflate-rawを使います。未対応のブラウザは、対応環境を案内してください。
・ExcelがCSVを開いている場合も、ブラウザから通常の読取を試みます。ただし、OSや共有先による排他読取禁止を回避できると保証しないでください。取得に失敗したら、表示済みデータを保持してエラーにしてください。

現在の制限を維持すること：
・CSVおよびExcelのファイルサイズ：64MiBまで。
・Excel内の1つのXML：32MiBまで。
・ZIP展開後の合計サイズ：256MiBまで。
・ZIPのエントリ数：10,000まで。分割ZIP・ZIP64は対象外です。
・ZIPの構造、内部パス、展開サイズ、CRC等を検証してください。
・DOCTYPE／ENTITYを含むXMLは拒否し、外部実体を解決しないでください。
・検証失敗時にログや振分表を修復して上書きしないでください。

13．担当者ランキング

・担当者1人につき1行を表示し、行を開くと、その担当者のCA詳細を表示してください。
・標準の並び順は合計件数の多い順です。同点なら元の表示順を維持してください。
・平日の列は、順位、担当者、チーム、未仕分、純粋未読、フラグ、合計、サポート投入状況を基本とします。
・土日の列は、順位、担当者、未仕分、合計、サポート投入状況です。チーム・純粋未読・フラグの独立列を表示しません。
・担当者名の近くに担当CA数を表示してください。
・平日だけ、担当CAが全部チェック済みかどうかに応じて「CAチェック未」「CAチェック済」を表示してください。
・平日はランキング上部にチーム別のCAチェック未件数を表示します。土日では領域ごと非表示にしてください。
・検索は担当者名またはCA名で行います。検索をクリアする操作を用意してください。
・平日のチーム表示をクリックすると、そのチームで絞り込み、解除できるようにしてください。土日はチーム絞り込みを出しません。
・平日の並び順は、合計、純粋未読、フラグ、未仕分の多い順から選べます。
・土日の並び順は、合計、未仕分の多い順です。
・CA詳細は合計件数の多い順、同点なら元の順です。
・同時に開く担当者の詳細は1つです。別の担当者を開くと、前の担当者の詳細を閉じてください。
・同じ担当者を再度クリックすると詳細を閉じます。
・詳細をスクロール中は、現在開いている担当者の行をランキング内の上部に固定し、誰のCAを見ているか分かるようにしてください。
・固定行と通常行を複製する場合は、DOMのidを重複させないでください。
・検索や絞り込みは表示対象を変える機能です。全体のダッシュボードや対応余力を、検索結果だけの数字に変えないでください。

14．担当CAカードと、CAチェック

・CAごとに、CA名、組織、件数、CALIB・Canvasリンク、サポート欄を表示してください。
・サポート欄の左に、CAごとの「サポ希望」チェックボックスを配置してください。担当者1人に1つのチェックボックスにはしません。
・サポート氏名はCAごとに最大3名です。空き枠から追加できます。

平日：
・初期状態のCAチェックボタンは「CAチェック未」です。
・チェックすると「CAチェック済」になり、共有保存します。
・チェック前は、サポート投入・解除、サポ希望、コミットの操作を有効にしないでください。
・CAチェックを取り消す独立ボタンは、現在のUIにはありません。追加しないでください。

土日：
・CAチェックはありません。「CAチェック未／済」ボタンも表示しません。
・担当者の「CAチェック未／済」表示、ランキング上部のチェック未集計も出しません。
・サポート投入とサポ希望は、CAチェックを条件にしないでください。
・土日の操作のために、平日の共有CAチェックを自動でチェック済みにしないでください。

共通：
・共有先が未接続、保存できない状態、またはCAがコミット済みなら、対応する操作を適切に制限してください。
・操作条件は、ボタンの見た目だけでなく、クリック時にも確認してください。

15．サポート投入・解除

・空き枠の「＋ 追加」からサポート氏名を入力します。
・氏名は前後空白を除去したうえで1～30文字です。同じCAに同じ氏名を重複登録しないでください。
・日本語入力の変換確定Enterを、登録確定と誤認しないようにしてください。
・Enter、または入力欄からフォーカスが外れたときに、次の確認を出してください。

確認タイトル：サポート投入の確認
確認文言：入力を確定しますか？
ボタン：はい／いいえ

・「はい」で共有保存します。「いいえ」やEscapeでは共有操作を保存しません。
・Enterとフォーカス離脱で、確認が二重に出たり、同じ氏名が二重保存されたりしないようにしてください。
・保存に成功する前に、登録済みの見た目に確定させないでください。
・登録済みの氏名にカーソルを合わせたときのポップアップは、入力されている氏名だけを表示してください。
・「クリックでサポート解除」というポップアップの追加文章は不要です。
・現在の実装では、登録済みの氏名をクリックした後、確認してサポートを解除します。この確認付きの解除動作は維持してください。
・解除の確認文言は「サポートを外れますか？」、ボタンは「はい／いいえ」です。
・解除は対象の登録IDを指定して終了を記録し、別の利用者が追加した新しい登録を古い画面から誤って解除しないでください。
・担当者カードのサポート人数は、未コミットの担当CAに投入中の氏名を重複なく数えます。
・同じ人が同じ担当者の複数CAをサポートしても、担当者カードでは1名です。
・CAごとの3枠表示と、担当者単位の重複除去した人数を混同しないでください。

16．サポ希望

・CAごとのサポ希望を共有してください。
・平日はCAチェック未の間、チェックボックスを非活性にします。土日にはCAチェック条件がありません。
・サポ希望があるCAを持つ担当者のサポート投入状況に、「サポ希望」と赤系の文字で表示してください。
・コミット済みのCAは、担当者のサポ希望表示の判定対象にしません。
・CAのサポート投入が3名になったら、そのCAのサポ希望を自動的に外してください。
・3人目の投入と希望解除は、1つの共有操作として処理してください。片方だけ保存される状態を避けます。
・3名の間は、サポ希望を再びチェックできないようにしてください。
・サポートが2名以下に戻っても、希望を勝手に再チェックしません。必要なら利用者が再度チェックします。
・希望の解除は、読込時点の希望のIDを確認し、他の利用者が新しく付け直した希望を消さないでください。

17．17時以降のコミット・取消

時刻はPCのローカル時刻を使います。コミットは17:00以降に操作できます。
時刻の変化を定期的に反映し、17時を過ぎた後にHTMLを開き直す必要がないようにしてください。現在の更新間隔は30秒です。

平日の表示：
・17時前は、CAチェック未／済のボタンを表示します。
・17時以降、CAチェック済の位置を「コミット」ボタンに置き換えます。
・サポート追加欄の右側に別のコミットボタンを増やさないでください。
・17時以降もCAチェック未なら、「CAチェック未」のままです。
・17時以降にCAチェック未を押してチェックを完了すると、その位置はコミットボタンになります。

土日の表示：
・CAチェックボタンはありません。
・17時以降、コミットボタンだけを表示します。

コミット時：
・対象CAを確認してから、共有保存してください。
・CAカードをグレーアウトし、CAの残件数の表示を0にします。元のログ件数そのものは消去しません。
・そのCAの投入中のサポートを終了し、サポ希望を解除してください。
・これらは1つの共有操作として保存してください。

担当者ランキングが変わるタイミングは、特に重要です。
・担当者に割り当てられたすべてのCAがコミットしたときに、その担当者の残件数を0にしてください。
・一部のCAだけがコミットした段階では、担当者の純粋未読・フラグ・未仕分・合計のランキング値は減らしません。
・全体の件数と対応余力の残件数も、担当者単位のこの判定に合わせます。
・担当者のすべてのCAがコミットしたら、担当者カードもグレーアウトしてください。
・件数が0のCAも含め、「割り当てられたすべてのCA」を判定対象にします。

例：担当者AにCAが3名あり、合計が30件、20件、10件の場合。
最初：担当者Aは60件。
1名目をコミット：対象CAだけグレー、担当者Aは60件のまま。
2名目をコミット：担当者Aは60件のまま。
3名目をコミット：担当者Aを0件にしてランキングを更新し、全体の残件数から60件を差し引く。

取消時：
・コミット取消の確認後、共有状態を更新してください。
・全CAコミット済みの担当者で1名でも取消したら、その担当者の最新の取込件数の合計を復帰させます。
・取消したCAの件数だけを復帰させる計算にはしません。
・コミット時に終了したサポートを、取消だけで自動的に再投入しないでください。
・取消対象のコミット時刻と共有状態のrevisionを確認してください。別の利用者が更新・再コミットした状態を古い確認画面から消さないでください。

18．右のダッシュボード

平日：
・全体の残件数、純粋未読、フラグ、未仕分を表示します。
・全体の残件数＝純粋未読＋フラグです。未仕分を加えません。
・除外担当者の件数は加えません。
・全CAコミットの担当者は0件として反映します。一部コミットだけでは減らしません。

土日：
・全体の残件数と、CSV見出し由来のF～M列の8項目、Q列の参考項目、R列の未仕分を表示します。
・項目の表示順はF～M、Qの参考項目、Rの未仕分です。
・F～Mの項目名の左にチェックボックスを設置します。最初は8項目すべてチェックです。
・集計前はチェックを操作できない状態にしてください。
・チェックを外した項目はグレーアウトし、その項目を全体件数、担当者・CAの合計、ランキング、対応余力の残件数から除外します。
・グレーアウトした項目の表示件数まで0にしないでください。元の集計件数を見えるようにします。
・再チェックすると、元の件数を合計へ戻します。CSVの再読込は不要です。
・Q列と未仕分にはチェックボックスを付けません。
・Q列と未仕分は、常に合計・ランキング合計に含めません。
・Q列も、CSVの見出しを表示名に使います。固定の架空名を付けないでください。
・土日のダッシュボードのチェック状態は共有しません。別の利用者の表示・集計対象を変更しないでください。
・対象項目のチェックはこの画面の状態として保持し、共有JSONには保存しません。
・同じ日・同じ項目名で再集計した場合は、その画面の選択を維持します。日付や項目名が変わったら、8項目すべてチェックへ戻します。
・HTMLを開き直した場合も、8項目すべてチェックで開始します。
・除外担当者と全CAコミット担当者の扱いは、平日と同じ基準です。

19．対応余力

・平日：1人当たり16件／時。
・土日：1人当たり10件／時。
・人数はCAの人数ではなく、対象となる担当者数です。
・サポート人数を勝手に対応人数へ加算しないでください。
・サポ希望やCAチェックの有無だけで対象人数を変えないでください。
・担当なし等の除外区分、担当CAがない担当者は対象人数から除きます。
・通常担当者を、コミット済みという理由だけで人数から除きません。

計算方法：
集計時刻を分に換算する。
計算開始＝9:00と集計時刻の遅い方。
残り時間＝18:00－計算開始。ただし負なら0。
集計時刻が14:00より前なら、昼休憩60分を引く。14:00以降なら引かない。
控除後の残り時間が負なら0。
想定処理件数＝対象担当者数×1人当たり件数／時×残り時間（分）÷60。
対応余力＝想定処理件数－全体の残件数。

・正の値なら「余力あり」、負なら「余力なし」、0なら「過不足なし」と表示してください。
・必要な場合は小数1桁まで表示し、正の余力は＋記号を付けます。
・集計時刻はHH:mmで入力・修正できます。時・分の範囲を検証してください。
・未集計なら「未集計」、不正な時刻なら「時刻を確認」と表示し、正しい計算結果のように見せないでください。
・余力再計算は、入力した時刻を使って再計算するだけです。CSV選択や共有再接続を起動しません。

計算例：対象担当者3人、全体残件数100件、集計時刻13:00。
残り5時間から昼休憩1時間を引いて、4時間。
平日：3×16×4－100＝＋92件。
土日：3×10×4－100＝＋20件。

20．CALIB・Canvasリンク

・振分表のF列からCALIB、M列からCanvasのURLを取得してください。
・表示文字列が「Canvas」等でも、セルのハイパーリンクの実URLを取得してください。
・URLが取れないCAがあっても、業務量の集計自体は止めないでください。
・該当リンクの近くに、未設定・無効等の理由を表示してください。
・リンクはhttpまたはhttpsを検証してください。javascript:、data:、file:等は開かないでください。
・新しいタブ／ウィンドウで開き、noopener、noreferrerを付けてください。
・CALIBには日付を追加しません。
・Canvasには、押した当日のPCの日付をyyyy/mm/ddでURLの最後に追加してください。
・末尾のスラッシュの有無を処理して、二重スラッシュを増やさないでください。

例：Canvasの元URLが https://canvas.example.internal/path/ で、当日が2026年10月10日なら、
https://canvas.example.internal/path/2026/10/10 を開く。
このURLは説明用です。実際の社内URLをハードコードしないでください。

・既存のURL構成を、無断でクエリ方式や別の日付形式へ変更しないでください。
・現在の実装はホストの許可リストや利用者認証を持ちません。強化案があれば提案欄に分け、社内の許可ホストが不明なまま挙動を変更しないでください。

21．平日・土日の画面切替

・モードを切り替えるだけで、CSV選択を自動的に始めないでください。
・平日と土日は、その画面で取り込んだデータ、集計時刻、検索、並び順、展開状態、スクロール位置等を分けて保持してください。
・平日→土日→平日に戻った際に、平日の表示データを土日データで上書きしないでください。
・これは開いている画面内の保持です。HTMLを閉じてもすべての取込結果が永続化される仕様にしないでください。
・共有操作は、同じ日付・同じ組織・同じCAに対して共通です。モードを切り替えて別の履歴として二重登録しないでください。
・土日の項目チェック、検索、スクロール、モード選択は、他の利用者へ共有しません。
・入力中、確認中、保存中、集計中、ファイル選択中は切替を制限し、「入力・保存・集計が完了してから切り替えてください。」等の案内を表示してください。

22．共有フォルダの保存方式

・各PCにはアプリ一式を置き、全利用者が同じ共有フォルダを設定して使用する方式にしてください。
・ログの取込結果全体を共有JSONに書き出す方式ではありません。
・共有するのは、CAチェック、サポート投入・解除、サポ希望、コミット・取消の操作です。
・1つの大きな日次JSONを全員が読み替えて上書きする方式にしないでください。他の利用者の操作が消える原因になります。
・操作1回につき、一意な操作JSONファイルを1つ追加する方式を使ってください。

保存先：共有先／WORKLOAD_HTML_DATA／yyyymmdd／op-h-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.json

・xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxは、crypto.getRandomValuesで作る16バイト由来の小文字16進数32文字です。
・操作IDはh-から始め、そのIDとファイル名が一致することを検証してください。
・保存済みの操作JSONは変更しません。取消・解除は新しい操作を追加して表現してください。
・同じIDのファイルに別の内容があれば上書きしないでください。
・日付はPCのローカル日付です。当日のフォルダだけを読み、過去の日付の全JSONを毎回読みません。
・過去の履歴を、自動で削除・書換・アーカイブする機能は追加しないでください。
・新しい操作を読み、既存の操作と合わせて状態を再構築してください。
・イベントの順序はclockとIDで決定し、どのPCでも同じ順序になります。
・clockはLamport型の論理時計とし、取り込んだ最大値を考慮して次の操作に進めます。
・同じCAの同時追加でも3名までの制限を適用し、4人目相当の競合は説明してください。別CAの同時操作を捨てないでください。
・共有データはおおむね3秒間隔で更新します。ファイル変更の反映が完全に即時であると説明しないでください。
・変わらない操作の本文はキャッシュし、既存ファイルのメタデータ確認は1巡回当たり最大16件等に分散して、共有先へ不要な大量アクセスをしないでください。
・CA・担当者の索引と集計キャッシュを使い、操作ごとにすべてを何度も走査しないでください。

操作JSONの外側の形式：
{
  "schemaVersion": 1,
  "application": "WorkloadRankingHTML",
  "id": "h-32文字の小文字16進数",
  "date": "yyyymmdd",
  "clock": 1,
  "stamp": "ISO 8601のUTC時刻。ミリ秒3桁とZを含む",
  "action": {
    "kind": "操作種別",
    "organization": "組織",
    "caName": "CA名"
  }
}

上は形式説明です。ID・日付・時刻をそのまま固定値として保存しないでください。
clockは1以上1,000,000,000,000以下の安全な整数です。stampをローカル日付へ戻した結果とdateが一致することを確認してください。

操作種別：
check：CAチェック。
add：サポート追加。supportNameを指定する。
finish：サポート終了。entryIdで対象を指定する。
supportRequest：CA単位のサポ希望。requested、解除時のrequestId等を指定する。
commit：CAのコミット。
cancelCommit：コミット取消。committedAt、revisionを確認する。
staffSupportRequest：既存履歴を読むための互換操作。新UIを担当者単位の希望に戻すためには使わない。

・actionの詳細、状態再構築、旧形式との互換処理は、元コードがある場合はworkload-share.jsをそのまま基準にしてください。
・異なる用途のJSONを読み込んで、無条件に共有操作として扱わないでください。

23．保存待ち、再試行、閉じるときの動作

・利用者が「はい」で確定した操作は、共有書込の前に、localStorageへ保存待ちとして記録してください。
・現在のキー接頭辞はworkload-html.pending.v1.です。元コードがある場合は互換性を維持してください。
・保存待ちには、操作ID、日付、確定時刻、操作内容、共有先識別子、共有先名、生成済みイベント等を保持します。
・localStorageに保存できないときは、そのまま共有へ書いて成功扱いにしないでください。
・再試行は同じID・同じイベントを使います。再試行のたびに別IDの操作を作って二重投入しないでください。
・共有への書込は、createWritable、write、close後に内容を読み返して確認してください。失敗時は可能な範囲でabortしてください。
・保存した内容が共有履歴として確認できるまで、保存待ちを消さないでください。
・書込失敗、権限失効、接続切れでは、直前に確認できていた状態を保持して、未保存を明示してください。
・未保存の操作を登録済みとして表示し、後で黙って消す動作にしないでください。
・保存待ちがあるときは、通常の共有更新やログ集計時に再試行します。
・別の利用者の更新により操作が成立しなくなった場合は、競合の理由と未反映を表示してください。終端の競合を永遠に再試行しないでください。
・共有先の切替時は、保存待ちを別フォルダへ移送しないでください。
・同じフォルダ名の別フォルダを同一共有先と誤認しないよう、ハンドルのisSameEntry等で確認してください。
・未確定入力や保存待ちがある場合は、ブラウザを閉じる際に可能な範囲で警告してください。
・ブラウザが終了した後もJavaScriptが動き続けて保存する、と説明・実装しないでください。
・保存待ちが残った場合は、同じブラウザのプロファイルで開き直し、同じ共有先に再接続して回復できるようにしてください。
・確定前の入力文と、確定済みの保存待ちを混同しないでください。

24．共有履歴の不正・破損と、既存形式

・JSON構文、schemaVersion、application、ID、ファイル名、日付、時刻、clock、操作種別、必要な名前を検証してください。
・保存済みで読込済みの操作ファイルが削除・変更された場合は、検出してエラーにしてください。
・内容がおかしいからといって、空の正常データへ初期化したり、既存の共有ファイルを上書きしたりしないでください。
・書込途中と思われる新規の空ファイルと、確認済みファイルの破損を区別してください。
・エラー時は最後に確認できた状態を保持し、不確かな新状態へ進めないでください。
・1つの操作ファイルは2MiBまで、旧形式の日次データは16MiBまで、当日操作は50,000件までです。

元コードの互換機能：
・共有先直下のyyyymmdd.json（schemaVersion 2）やyyyymmdd.jsを、基準履歴として読む場合があります。
・旧JSをscriptタグ、eval、Functionで実行しないでください。決まった形式からJSONを抽出し、JSONとして検証する方式です。
・HTML版から旧ファイルを勝手に更新しないでください。
・新しいHTMLの操作履歴と、HTAの書換を同時に動かす運用を前提にしないでください。
・旧基準履歴が途中で変わる場合は、安全に停止して確認を促してください。
・元コードがない状態で互換処理を作った場合は、実データの互換確認が必要と明記してください。

25．セキュリティ上の実装条件

・CSV、Excel、共有JSON、氏名、組織名、項目見出し、エラー文は、すべて外部入力として扱ってください。
・名前や見出しをそのままinnerHTML、onclick等へ埋め込まず、textContent、適切なエスケープ、安全なID生成を使ってください。
・元コードのHTML生成方式を使う場合は、すべての文字列と属性を確実にエスケープしてください。
・__proto__等を名前に含む場合でも、辞書やオブジェクトの状態が壊れないようにしてください。
・操作IDとCAの識別子を、表示名をそのままDOMやJSの識別子にしたものにしないでください。
・外部URLの実行やマクロ、数式、旧JSの実行を行わないでください。
・ログ、個人名、共有履歴を、インターネットや解析サービスへ送信しないでください。
・トークン、パスワード、認証情報をソースに埋め込まないでください。
・不正データの検証と、操作者の本人確認を混同しないでください。
・現在の方式には、ログイン、署名、サーバー側の認可、改ざん不能な監査記録はありません。
・共有先に書込権限を持つ人が、正しい形式の操作JSONを自分で作った場合、アプリだけで本人の操作かを証明できません。
・そのため、配布HTML・JSを変更できる人と、共有先へのアクセス権は、運用側で管理する前提をREADMEに記載してください。
・「AWS内だから安全」「HTMLだから問題なし」「外部に接続しないから完全に安全」という断定をしないでください。
・セキュリティ強化のためにサーバー、認証、許可ホスト、CSP等を追加する案は、再現対象の実装と分けて提案してください。既存機能を壊す変更を黙って入れないでください。

26．処理速度と、画面の安定性

・検索入力は、現在の目安である150ms程度のdebounceを使い、キー入力ごとに重い再集計をしないでください。
・担当CA詳細が多い場合は、現在の32件単位のような分割描画で、操作できる状態を保ってください。
・描画のためにフォーカス、入力内容、IMEの変換状態、確認ダイアログ、スクロール位置を失わせないでください。
・共有の3秒更新のたびに、全てのJSON本文とExcelを読み直さないでください。
・過去の日付の履歴を、当日の集計のたびにすべて列挙・読込する構成にしないでください。
・読み込み、保存、確認、モード切替を排他管理して、同じ処理を二重に走らせないでください。
・性能確認の結果は、使用した件数と環境を添えてください。測定していない応答時間や最大人数を保証しないでください。

27．受入確認

完成前に、少なくとも次のケースを確認し、期待値と実際の結果を示してください。
元コードがある場合は、平日の既存処理が変わっていないことも確認してください。

A．読込・照合
1）未設定でログ集計を押すと、必要な設定を案内する。
2）同じブラウザで開き直すと設定済みの場所を再利用でき、必要なら許可を確認する。
3）平日は未読→フラグの2回選択、土日は3回選択になる。
4）対象の日付・月フォルダがない場合に、別の日付を黙って読み込まない。
5）CSV選択取消、3つ目のCSVの不正、振分表の不正で、前の正常な集計を保持する。
6）平日・土日・振分表とも3行目開始で、2行目をデータにしない。
7）土日の見出しを2行目から取得し、B列がエリア、C列が組織の場合に正しく照合する。
8）土日の同一ファイルの再選択を検出し、別ファイルの同一CA行は合算する。
9）土日の3CSVの項目名が異なる場合に停止する。
10）全角数字、引用符内のカンマ・改行、UTF-8・Shift_JIS等を正しく扱う。
11）不足列、欠けた組織・CA名、負数、小数、文字化け、負の純粋未読を検出する。
12）違う組織の同名CAを分け、振分表の未照合CAだけを担当なしにする。
13）振分表の重複矛盾を検出し、ログにない振分表CAは0件で表示する。

B．表示・集計・余力
14）平日では純粋未読＋フラグが合計で、未仕分は除外される。
15）土日ではF～Mの8項目が合計で、Q・Rは表示のみ、チェックなしになる。
16）土日の項目チェックを外すとグレーになり、表示件数は残り、合計・ランキング・余力が変わる。
17）別の利用者の土日項目チェックが変わらない。共有JSONも作られない。
18）平日・土日を往復して、取込データや表示状態を混同しない。
19）土日にはチーム、CAチェック、チェック未の集計領域がない。
20）検索やチーム絞り込みで全体のダッシュボードの件数を減らさない。
21）13時の計算例が平日＋92、土日＋20になり、14時以降は昼休憩を二重に引かない。
22）9時前・18時以降・不正時刻の計算と表示が仕様どおりになる。
23）ライト・ダークの両方で順位、合計、集計ボタン、エラー、グレー表示が読みやすい。
24）1920×1080でサポート欄がつぶれず、長い名前でも数値・ボタンが重ならない。

C．CA操作
25）平日CAチェック未ではサポート操作とサポ希望が非活性、土日ではチェック条件なしになる。
26）日本語IMEのEnterで誤登録せず、確認の「はい」で1回だけ追加される。
27）追加・解除の「いいえ」では共有操作を作らない。
28）同じCAの同名サポートと4名以上を拒否する。別CAで同じ人を投入した場合、担当者カードでは重複なく数える。
29）3人目の投入でサポ希望を同じ操作として解除し、2人に戻っても勝手に希望を復活させない。
30）17時前後で平日のチェック済の位置がコミットへ切り替わり、チェック未はそのままになる。
31）17時以降にチェック未を押すと、チェック完了後はコミットが表示される。
32）担当CAが3名いる場合、1名・2名コミットでは担当者の合計を維持し、3名目で0件・担当者グレーになる。
33）全CAコミットから1名を取消したら担当者の全件数が戻り、終了済みサポートは自動復活しない。
34）CALIBには日付を付けず、Canvasには当日のyyyy/mm/ddを末尾に付ける。

D．共有・障害
35）2つの画面から別CAへ同時操作しても、一方の操作が消えない。
36）同じCAへの同時追加や古い希望解除・コミット取消で、制限と競合検証が働く。
37）書込拒否、接続切れ、close失敗、localStorage失敗を模擬し、成功扱いにしない。
38）保存待ちの再試行と、開き直しての再接続で、操作IDを変えずに回復し、二重投入しない。
39）同じ名前の別共有フォルダへ保存待ちを誤送信しない。
40）不正JSON、日付・ID・名前の不一致、読込済み操作の変更・削除を検出し、既存ファイルを上書きしない。
41）巨大ファイル、展開サイズ超過、不正XML、危険なURL、HTMLに見える氏名で、実行や画面崩れを起こさない。
42）旧JS履歴を実行せず、互換処理を確認できた範囲と未確認の範囲を区別する。

・共有の障害・同時操作は、可能なら模擬FileSystemハンドル等でも確認してください。
・実際のEdgeと職場の共有フォルダでしか確認できない項目は、その項目を分けて提示してください。
・検証できない項目を「合格」「動作確認済み」と記載しないでください。
・模擬テストの成功を、実際のAWS・社内端末での動作保証にしないでください。

28．納品内容

・起動可能なHTMLと、必要なすべてのJS、READMEを、一式で提出してください。
・既存のサンプルを流用できない場合は、架空のCA・担当者・組織を使ったサンプルCSVと振分表を用意してください。
・実際の個人名、社内URL、機密ログを、公開用のサンプルやテストへ流用しないでください。
・ファイルを作成できる環境なら、ダウンロードできるZIP一式を作ってください。
・ファイル添付ができない環境なら、ファイル名を明記して各ファイルの完全なコードを順に提出してください。省略記号でコードを欠落させないでください。
・出力制限がある場合は、分割しても最後にファイル一覧と欠落がないことを示してください。
・元コードを基にした場合は、変更ファイルと差分を示し、対象外ファイルが変更されていないことを確認してください。
・READMEには、初回設定、平日・土日の使い分け、フォルダ例、毎日のログ集計、権限の再確認、未保存時の回復、設定ファイルの編集箇所を記載してください。
・READMEに、ブラウザを閉じた後は処理が継続しないこと、共有の本人確認がないこと、職場で必要な確認を記載してください。
・完了報告は、日本語で「何ができるか」「起動方法」「確認した内容」「未確認の項目」を簡潔にまとめてください。
・機能追加や安全性向上の提案がある場合は、今回実装した機能と分けて提示してください。

以上の条件に従い、現在のHTML最新版と同じ業務の流れになるように実装してください。
