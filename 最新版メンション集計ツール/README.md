# メンション集計ツール v0.2（共有フォルダ・日付別保存版）

業務量モニター3.0のHTML版と同様に、操作ごとに別のJSONを共有フォルダへ保存します。
**Python、HTA、拡張機能、常時起動する保存担当PCは不要です。**

## 使い始める

1. ZIPをすべて展開し、index.html と mention-share.js を同じ場所に置きます。
2. 通常のEdgeまたはChromeで index.html を開きます。
3. 「担当者：未登録」から自分の名前を登録します。設定画面は「担当者：名前」から開きます。
4. 画面右上の「共有を接続」を押し、全員で同じ親フォルダを選び、読み書きを許可します。
5. 「CSVを設定」で当日対象の出力CSVを選び、「集計」を押します。CSVを設定するまでは集計できません。
6. 他の担当者も同じ共有先に接続し、当日対象のCSVを集計すると、対応状況を共有できます。

共有先はブラウザーに記憶します。次回、権限が保持されていれば自動で接続します。再許可が必要な場合は「共有を再許可」を押します。変更するときは設定の「共有先を選択・変更」を使います。

共有フォルダへの書き込みは、実際にテストファイルを作成・保存・読み戻せた場合に有効にします。初回のフォルダ選択と許可は必要です。

業務量モニターのHTML版と同じ、ブラウザーのフォルダ読み書き機能を使います。社内ポリシーでこの機能が禁止されている場合、この版も共有できません。業務量モニターと同じ環境・開き方で確認してください。個々のPCのローカルフォルダや、同期に時間がかかるクラウド同期フォルダを共有先にしないでください。

## 画面だけ試す

取り込み前の「サンプルで操作を試す」で架空の案件を操作できます。サンプル中は共有先や実際の案件へ書き込みません。CSVの集計またはJSONの復元が成功した後は、設定画面も含めてサンプルボタンを非表示にします。

共有を接続しない場合は単独モードで、このブラウザー内に保存します。別PCへは反映しません。共有接続時に、単独モードの案件は自動では移しません。共有したい案件は、接続後に元のCSVから集計してください。

## 案件とCSV

- 一覧：チェック、依頼No.、組織、CA名、出社状況、メールメモ、期日または面接日程、タイプ、対応状況、メモ。
- 依頼No.は保存データへの受付順です。CSV内の依頼No.ではなく、完了・検索・並べ替えでも変わりません。
- カードか右端の「▾」で、送信日時・メールメモ・タイプ・オプション・代理CA1〜8・依頼者・リクエストIDを表示します。別のカードを開くと前のカードを閉じます。
- 代理CA1〜8は一度に表示します。タイプは折り返さず横スクロールできます。
- CA名をダブルクリックするとコピーします。検索対象はCA名・担当者です。
- RequestIDが未取込の案件だけ追加します。CA名や依頼No.が同じでも、RequestIDが違えば別件です。
- 同じCSVを再集計しても、既存の依頼内容・担当者・メモ・「済」を保持します。
- 共有データは日付ごとに分かれます。同じ日の中でRequestIDの重複を防ぎ、別日へ過去の案件は自動で引き継ぎません。
- 起動時は一覧を空にし、今回集計したCSVに含まれる案件だけを表示します。保存済みの履歴や担当状況を削除する動作ではありません。CSVに過去の依頼が含まれていれば、その依頼も表示対象になります。
- UTF-8／Shift_JIS（CP932）、引用符、カンマ、セル内改行に対応。最新版の21列・代理CA8名と、代理CA6名・3名の旧形式を列名で読みます。
- 必須列は「依頼No.」「組織」「CA名」「RequestID」です。
- RequestIDが空の行や列数不一致は除外し、結果に表示します。引用符が閉じていなければ、その回の集計を中止します。
- フォームの出力は行末に改行を付けます。末尾に改行がない行は、書き込み途中の可能性があるため次回に回します。
- CSVへの参照を保持できる場合は「集計」で同じファイルの最新内容を読みます。許可・開き方の制限で保持できない場合は、集計のたびに同じCSVを再選択します。
- 元のCSV、メンション依頼フォーム、Pending、Workerは変更しません。

## 対応開始・完了

1. 依頼No.の左をチェックします。
2. 「対応開始」でCA名と登録済みの担当者名を確認し、「はい」を押します。
3. 担当者名を表示します。自分が対応中のカードだけ水色になり、チェックは外れます。他の人が対応中の案件はチェックできません。
4. 自分が対応中の案件を再度チェックし、「対応完了」→「はい」で「済」になります。詳細が開いていれば閉じ、グレー表示で一覧の下へ移動します。

並びは「自分の対応中 → 他の人の対応中（担当者別）→ 未対応 → 済」です。同じ担当・状態の中では受付順です。自分を先頭にする表示は各ブラウザーだけに適用します。

未対応と対応中を同時に選択すると、開始・完了ボタンは使えません。案件は個別にチェックします。全選択ボタンや状態タブはありません。完了案件の取消や担当者変更は、この版にはありません。

保存前に共有履歴を再確認します。既に対応が開始されている案件があれば、その操作で選択した全件の書き込みを中止します。ポップアップの「はい」は全選択解除、「いいえ」は競合案件だけを選択から外します。

## 同時操作でできること・できないこと

**この方式は、別PCからの完全に同時の開始を、その瞬間に排他ロックする方式ではありません。**

- 操作ごとに一意なファイルを作り、別の人のJSONを上書きしません。
- 約3秒ごとに共有を確認します。回線が遅い場合は反映も遅れます。
- 操作を全PCで同じ順序に並べ、同じ案件の開始やメモが競合した場合は、片方を未反映にします。
- まとめて開始・完了する操作は、1件でも競合すれば、その操作全体を未反映にします。
- 同時操作のファイルが遅れて見えた場合、一度反映された表示が後から変わることがあります。必ず実際の二重対応を防げるという保証はありません。
- 競合は画面下部のお知らせと設定画面の「共有の状態」に表示します。対象案件の担当者・対応状況を確認してください。
- 完了操作は、画面で見ていた開始操作と結び付けて検査します。遅れて別の人の開始が有効になった場合、古い担当状態に基づく完了は未反映にします。

「誰かが先に開始していることを読み取れた場合は保存しない」は実装しています。完全な同時操作でも絶対に二重対応させないことが必須なら、この共有フォルダ方式だけでは満たせません。

## メモ

Enter または欄から移動すると保存します。改行は Shift+Enter です。

同時編集では上書きを止め、共有先の最新メモと自分の入力を確認する画面を出します。必要な内容をまとめ、「確認した内容で保存」を押してください。ネットワーク等で保存に失敗しても入力を保持し、確認済みの操作は端末内の保存待ちから再送します。

## 保存先と再送

共有フォルダ内の以下へ保存します。

`MENTION_DESK_DATA/YYYYMMDD/operations/op-h-操作番号.json`

日付はPCのローカル日付です。日付フォルダは自動作成するため、利用者は全員同じ親フォルダを選びます。起動・再接続時は当日分へ接続します。開いたまま日付が変わると新規集計・開始・完了を止めるので、メモを保存したうえで「共有を再接続」し、当日のCSVを設定・集計してください。

保存待ちの操作は元の日付フォルダへ再送します。旧版の日時なし保存待ちは旧フォルダへ戻します。**旧版の `MENTION_DESK_DATA/operations` にある履歴は日付フォルダへ自動移行しません。** 全員の版をそろえ、新しい日の業務開始時から切り替えてください。

1ファイルが、取込・対応開始・対応完了・メモ編集のいずれかの操作です。操作履歴を読み合わせて一覧を復元するため、単一のrequests.jsonは更新しません。大きなCSVは最大500件かつ約900KB以内に分けて取り込みます。途中で失敗した場合、再集計すれば既存RequestIDを飛ばして続けられます。

確認済みの操作は、共有へ書く前にブラウザー内へ退避します。保存失敗や保存後の確認失敗では、同じ操作番号のまま再送します。自動更新、または「最新に更新」で再試行します。

- 保存待ちがある間は画面を開いたままにしてください。ブラウザーの終了時に警告を要求します。
- 閉じた後に保存を続ける補助プログラムはありません。
- 再開する場合は、同じHTMLの場所・ブラウザープロファイル・共有先を使います。
- 保存待ちのままHTMLを移動したり、ブラウザーの保存データを消したりしないでください。
- 保存待ちがある場合は、無関係な共有フォルダへの切り替えを止めます。
- 設定の「保存待ちの控え」で、端末内の保存待ちをJSONに書き出せます。この控えを共有フォルダへ直接置かないでください。
- 同じPCから複数画面を開いた場合、対応ブラウザーでは端末内の共有処理を順番に実行します。これは別PCとの排他ロックではありません。

## バックアップと保全

共有データのバックアップは、利用を止めたうえで MENTION_DESK_DATA フォルダ全体をコピーしてください。設定の「JSONを書き出す」は、現在読み込んでいる保存データ全体の控えです。一覧に表示していない案件も含みます。共有履歴全体の復元用ファイルではありません。「JSONから復元」は単独モード用です。

操作JSONは、使用中に編集・削除・置換しないでください。既に読み込んだ履歴の変更・削除を検知すると、同期と保存を止め、既存ファイルを上書きしません。読み込み済み履歴は小分けに内容を再確認します。変更の検知が即時とは限りません。

履歴は日付が変わっても削除しません。1日分の操作50,000件で保全のため停止します。大量の案件・履歴での速度は実際の共有フォルダで確認してください。

## セキュリティ上の前提

- 担当者名は誤操作を減らすための識別です。ログイン・本人認証・厳密な権限制御ではありません。同じ名前は同じ担当者と判定されます。重複する場合は拠点名等を付けて区別してください。
- 共有JSON、単独モードの保存データ、ブラウザー内の保存待ち、JSONの控えは暗号化しません。許可された従業員だけが利用できるPC・ブラウザープロファイル・共有フォルダで使ってください。
- 起動時に一覧を空にしても、保存先の実データは消えません。日付フォルダも自動削除しません。保管期間・バックアップ・廃棄は社内ルールで管理してください。未反映の保存待ちがある間は削除しないでください。
- 読み込み済みの共有履歴の改変・削除は検知して停止しますが、電子署名による認証ではありません。初回読み込みより前の改変や、共有フォルダに書き込み権限を持つ人による偽造を防ぐものではありません。
- 元CSVは読み取り専用です。共有への書き込みは選択先の専用フォルダ内に限定し、接続確認用に自分で作成した一時ファイルだけを削除します。
- このリポジトリの配布物にはコード・説明書・架空のサンプルだけを置きます。実業務のCSV、共有JSON、保存待ちの控えをGitHubに追加しないでください。
