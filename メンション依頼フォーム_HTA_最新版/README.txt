メンション依頼フォーム HTA 本番版 v28.31.2
============================================================
2026/09/14 モニター位置保持＋依頼2／3の下端見切れ対策
ベース：この修正PRのv28.31.1（mainのv28.31から派生）

■ 今回の修正
・v28.31.1で、モニター原点不明時に上へ持ち上げる補正を止めたため、
  依頼2／3の展開位置によって下側が画面外へ伸びる問題が再発していました。
・WindowsのMonitorFromWindow／GetMonitorInfoから実際のモニターと作業範囲を取得。
  拡張前のフォームが置かれているモニターを基準に、サイズと位置を同時に調整します。
・タスクバーを避けて画面内へ収め、拡張時は中央より少し上を目安に持ち上げます。
・画面の高さを超える場合は縦スクロール、幅を超える場合は横スクロールで、
  依頼3や下部の送信ボタンまで操作できます。文字やカードの自動縮小は行いません。
・最大化・最小化中の位置変更は行わず、ドラッグ中の自動調整は待機します。
・送信、CSV、Pending、Worker、入力項目はv28.31の処理を維持します。

■ 差し替え（今回の修正は下記6ファイルが必要です）
1. 開いているフォームを閉じ、現在のフォーム一式をバックアップします。
2. ZIP内の以下6ファイルを、使用中のHTAと同じフォルダへコピー・上書きします。
   ・メンション依頼フォーム.hta
   ・mention-form.js
   ・mention-form.css
   ・mention-layout.js
   ・mention-layout-host.ps1
   ・mention-layout-host.cs
3. HTAを起動し直します。
   mention-request-worker.js、書き込み用フォルダ、既存CSVはそのまま使用します。
   このZIPは差し替え用です。単独の新規フォルダとして起動する構成ではありません。

■ Windowsの自動調整について
・Windows 11の標準機能であるWindows PowerShell／.NETを使用します。
  同じフォーム専用の補助処理を1つ起動し、フォーム終了時に停止します。
・会社の設定などで補助処理を起動できない場合は、フォーム上部に
  「画面の自動調整が利用できません」と表示し、現在のウィンドウの中を
  スクロールして操作できる形に切り替えます。最大化しての操作も可能です。
・管理者権限への昇格や、PowerShell実行ポリシーの変更は行いません。

■ 実機確認（送信せずに確認できます）
1. PC側で起動 → 外部モニターへ移動 → 画面の下側にフォームを置きます。
2. 依頼1の必須項目を入力 → 依頼2を表示。
   同じモニター内で上へ補正され、下側がタスクバーの下へ隠れないことを確認。
3. 依頼2の必須項目を入力 → 依頼3を表示。
   同じモニターに留まり、縦スクロールで下部の送信ボタンまで操作できることを確認。
4. 依頼3／2を取消 → PC側へ戻して再び展開。同じように操作できることを確認。
5. 表示倍率の異なるモニター、左右・上下の配置で使用する場合も同様に確認。

■ 検証済みの範囲
・JavaScript：位置保持・安全なスクロール代替など26項目PASS。
・配布C#ソースのコンパイルと、位置・サイズ計算／通信書式79ケースPASS。
  左右・上下・負座標、100／125／150／200％の換算、下端見切れを確認。
・補助処理の起動、連続クリック時の最新サイズ送出、最小化の応答、
  補助処理の失敗／起動できない場合の代替動作を模擬して確認。
・ブラウザーで3件展開後の縦横スクロール、送信ボタンまでの到達、入力欄の編集を
  1540×744／1280×600の表示領域で確認。
・Windows/mshtaの実機でのAPI呼び出し、会社のPowerShell設定は未検証です。

メンション依頼フォーム HTA 本番版 v28.31
============================================================

■ v28.31 修正内容（Pending自己修復）

・送信時、通常の退避CSVと同内容の復旧用コピー「*.csv.recovery」を同時作成します
・復旧用コピーは通常のPending件数には数えません
・通常Pendingが部分欠落／列不正／依頼数不一致／依頼No.欠落などで読めない場合、
  Workerが復旧用コピーを検証し、正常ならPrimary Pendingを自動修復して送信を継続します
・通常Pendingそのものが消失してRecoveryだけ残った場合も、Workerおよび次回起動時に復元します
・共有CSVへの書き込み＋再読込確認が成功した後、Recovery → Primaryの順に削除して完了します
・Recoveryまで壊れている／読めない場合は自己修復せず、安全停止＋Pending保持とします
・v28.30の「__N1～__N3」期待依頼数チェック、依頼No.連続性チェックはそのまま維持します
・旧Pending（Recoveryなし）も従来どおり再送可能です
・共有CSV16列、RequestID、ロック、再読込確認、300秒タイムアウト、完了Popup仕様は変更していません
・⑧「同一RequestID・内容相違」対策は今回には含めていません

・出社状況が未選択の間は、オプションのチェック項目のみ非表示。

・引き継ぎ中は上記項目を編集不可とし、元の変更を依頼1→2→3の順に反映。
・チェック解除で引き継いだ項目をクリア。メールメモ以降は各依頼で入力します。
